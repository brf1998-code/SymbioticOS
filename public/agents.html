Improvement board

Which model does each job, and what the agents read before they touch this company's modules. Managers can change both; the platform principles are fixed and shown for reference.

Models

Propose
One call per feedback item: reads the module and drafts the proposal, picks UI vs functionality and the target screen. Small context, so a cheaper model is fine. Also restates requirements before functionality builds.
Build
The agent that edits the module files, many turns with file tools. Most of the spend. Sonnet 5 handles UI changes well; step up to Opus 5 for functionality changes that touch server logic and data, or when a build keeps missing.
Review
Independent cross-check of the diff on the functionality lane. One call, diff only, so a stronger model than the builder costs little here and catches more.
Prices are per million tokens, input / output. A typical UI build on Sonnet 5 runs 5 to 30 cents; the same on Fable 5.1 about five times that. Per-run and monthly caps still apply.

What the agents read

Sent with every proposal and build, in this order: platform principles, then this company's docs, then the module's reference doc. Plain markdown. Keep them short and concrete; the agent follows what is written here more reliably than anything in the feedback text.
